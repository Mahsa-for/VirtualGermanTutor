# Tavus and Google Cloud Run Configuration

This guide documents the production setup used for **My German Tutor**, including the Tavus PAL, custom LLM connection, Google Cloud Run deployment, environment variables, IAM permissions, verification, and common failures.

## Architecture

1. The browser calls the FastAPI backend on Cloud Run.
2. The backend creates a Tavus conversation with `POST https://tavusapi.com/v2/conversations`.
3. Tavus returns a `conversation_url`, which the frontend embeds.
4. During the conversation, Tavus sends OpenAI-compatible streaming requests to:

   ```text
   https://virtual-german-tutor-743231335063.us-central1.run.app/api/tavus/llm/chat/completions
   ```

5. The backend sends the conversation to Gemini through Vertex AI and streams the response back to Tavus.

## Important secrets

Two different secrets are required:

- `TAVUS_API_KEY`: created in Tavus. The backend uses it to call the Tavus API.
- `TAVUS_LLM_AUTH_TOKEN`: generated by us. Tavus uses it to authenticate when calling the backend custom-LLM endpoint.

Never commit either value. If a key is pasted into chat, source code, screenshots, or a public log, revoke it and generate a new one.

Generate the shared LLM token locally with Python:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

The generated value must be entered both as `TAVUS_LLM_AUTH_TOKEN` in Cloud Run and as the Custom LLM API key in Tavus.

## 1. Configure Tavus

### Create the PAL

1. Open the Tavus PAL Maker.
2. Select **New PAL**.
3. Give it a name such as `German Tutor`.
4. Select a Face and Voice.
5. Add a system prompt describing the tutor's behavior.

Example PAL prompt:

```text
You are a friendly and patient German tutor. Ask one short German question at a time, gently correct mistakes, and encourage the learner to try again. Keep responses concise and conversational.
```

The API-based integration does not require a Tavus Deployment. The application creates Conversations directly using the PAL ID.

### Configure the PAL custom LLM

Configure the PAL's LLM layer as a custom OpenAI-compatible LLM:

```text
Model: virtual-german-tutor
Base URL: https://virtual-german-tutor-743231335063.us-central1.run.app/api/tavus/llm
API key: the same value used for TAVUS_LLM_AUTH_TOKEN
```

Do not add `/chat/completions` to the Tavus Base URL. Tavus appends that route automatically.

### Create a Tavus API key

1. Open **API Keys** in Tavus.
2. Create a new key.
3. Store it securely.
4. Add it to Cloud Run as `TAVUS_API_KEY`.

Tavus API requests must send this key using the `x-api-key` header. They must not use `Authorization: Bearer`.

## 2. Prepare the source archive

If Google Cloud CLI cannot be installed locally, deploy through browser-based Google Cloud Shell.

From the local project directory, create an archive that excludes local dependencies, build output, the virtual environment, and `.env`:

```powershell
tar.exe -a -c `
  -f "VirtualGermanTutor-deploy.zip" `
  --exclude="frontend/node_modules" `
  --exclude="frontend/dist" `
  --exclude=".venv" `
  --exclude=".env" `
  Dockerfile backend frontend
```

Excluding `.env` prevents secrets from being copied into the source upload or container image.

## 3. Deploy using Google Cloud Shell

1. Open the Google Cloud Console.
2. Click the **`>_` Cloud Shell** button.
3. Upload `VirtualGermanTutor-deploy.zip` through the Cloud Shell menu.
4. Extract the archive:

   ```bash
   unzip -o VirtualGermanTutor-deploy.zip -d VirtualGermanTutor
   cd VirtualGermanTutor
   ```

5. Select the project and enable the required APIs:

   ```bash
   gcloud config set project germantutor-511509
   gcloud services enable \
     run.googleapis.com \
     cloudbuild.googleapis.com \
     artifactregistry.googleapis.com \
     aiplatform.googleapis.com
   ```

6. Grant the default build service account the Cloud Run Builder role:

   ```bash
   gcloud projects add-iam-policy-binding germantutor-511509 \
     --member="serviceAccount:743231335063-compute@developer.gserviceaccount.com" \
     --role="roles/run.builder"
   ```

7. Grant the runtime service account access to Vertex AI:

   ```bash
   gcloud projects add-iam-policy-binding germantutor-511509 \
     --member="serviceAccount:743231335063-compute@developer.gserviceaccount.com" \
     --role="roles/aiplatform.user"
   ```

8. Deploy the service:

   ```bash
   gcloud run deploy virtual-german-tutor \
     --source . \
     --region us-central1 \
     --allow-unauthenticated \
     --port 8080
   ```

The deployed service URL is:

```text
https://virtual-german-tutor-743231335063.us-central1.run.app
```

Unauthenticated access must be allowed because browsers and Tavus need to call the service.

## 4. Configure Cloud Run environment variables

Open:

**Cloud Run → virtual-german-tutor → Edit and deploy new revision → Containers → Variables & Secrets**

Add the following variables. Cloud Run provides `PORT` automatically, so do not set it manually.

| Name | Value |
|---|---|
| `APP_ENV` | `production` |
| `PUBLIC_BASE_URL` | `https://virtual-german-tutor-743231335063.us-central1.run.app` |
| `MOCK_MODE` | `false` |
| `TAVUS_API_KEY` | A valid, current Tavus API key |
| `TAVUS_SESSION_CREATE_URL` | `https://tavusapi.com/v2/conversations` |
| `TAVUS_SESSION_END_URL_TEMPLATE` | `https://tavusapi.com/v2/conversations/{session_id}/end` |
| `TAVUS_SESSION_PAYLOAD_TEMPLATE` | The payload shown below |
| `TAVUS_LLM_AUTH_TOKEN` | A random secret that exactly matches the Tavus Custom LLM API key |
| `TAVUS_MAX_DURATION_SECONDS` | `900` |
| `SESSION_CREATE_RATE_LIMIT_PER_MINUTE` | `8` |
| `GCP_PROJECT_ID` | `germantutor-511509` |
| `GCP_REGION` | `us-central1` |
| `GEMINI_MODEL` | `gemini-2.0-flash-001` |

Use this one-line conversation payload:

```text
{{"pal_id":"pf1e2dc225a6","conversation_name":"German Tutor - {level} - {topic}","conversational_context":"Learner level: {level}. Practice topic: {topic}.","policy":"eu","properties":{{"max_call_duration":{max_duration_seconds},"participant_left_timeout":10,"participant_absent_timeout":120}}}}
```

The doubled outer and nested braces (`{{` and `}}`) are intentional. The backend uses Python string formatting, so literal JSON braces must be escaped this way. Placeholders such as `{level}` remain single-braced.

Click **View diff & redeploy**, then **Deploy changes**. Environment-variable changes create a new Cloud Run revision.

For production, store `TAVUS_API_KEY` and `TAVUS_LLM_AUTH_TOKEN` in Google Secret Manager instead of plain environment-variable values.

## 5. Verify the deployment

### Health check

Open:

```text
https://virtual-german-tutor-743231335063.us-central1.run.app/api/health
```

Expected response:

```json
{"status":"ok","mock_mode":false}
```

If `mock_mode` is `true`, update `MOCK_MODE=false` in Cloud Run and deploy a new revision.

### Test the Tavus API key independently

Use Cloud Shell to test a key without placing it in shell history:

```bash
read -s -p "Paste the new Tavus key: " TAVUS_KEY
echo
curl -i \
  -X POST "https://tavusapi.com/v2/conversations" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ${TAVUS_KEY}" \
  --data '{"pal_id":"pf1e2dc225a6","test_mode":true}'
unset TAVUS_KEY
```

Interpretation:

- `200`: authentication and PAL access work.
- `400` or `404`: authentication worked, but the PAL ID or payload needs attention.
- `401`: the key is invalid, revoked, copied incorrectly, or from a different Tavus account.

## 6. Deploy later code changes

Cloud Run does not read the local `.env.example`, and editing local files does not update the deployed service automatically.

After changing the application:

1. Create a new deployment ZIP.
2. Upload it to Cloud Shell.
3. Extract it over `~/VirtualGermanTutor`:

   ```bash
   cd ~
   unzip -o VirtualGermanTutor-deploy.zip -d VirtualGermanTutor
   cd VirtualGermanTutor
   ```

4. Redeploy:

   ```bash
   gcloud run deploy virtual-german-tutor \
     --source . \
     --region us-central1 \
     --allow-unauthenticated \
     --port 8080
   ```

Existing Cloud Run environment variables should remain attached to the service when redeploying source without environment-variable flags.

## Troubleshooting

### `gcloud` is not recognized

The Google Cloud CLI is not installed or is not on the local Windows `PATH`. Either install the official Google Cloud CLI and reopen PowerShell, or use browser-based Cloud Shell. Cloud Shell requires no local installation and was used for this deployment.

### Not enough local disk space for Google Cloud CLI

Use Google Cloud Shell. Create a small ZIP locally, upload it, and run all `gcloud` commands in the browser terminal.

### Cloud Build `PERMISSION_DENIED`

Example:

```text
default service account is missing required IAM permissions
```

Grant `roles/run.builder` to the build account:

```bash
gcloud projects add-iam-policy-binding germantutor-511509 \
  --member="serviceAccount:743231335063-compute@developer.gserviceaccount.com" \
  --role="roles/run.builder"
```

Wait about one minute for IAM propagation and retry the deployment.

### Tavus conversation creation returns `401 UNAUTHORIZED`

Check all of the following:

1. The deployed backend sends the Tavus key as `x-api-key`.
2. `TAVUS_API_KEY` in Cloud Run contains the actual key, not placeholder text.
3. The key has not been revoked.
4. The value contains no quotes, leading/trailing spaces, or line breaks.
5. The Cloud Run revision containing the corrected code is receiving 100% of traffic.

The corrected backend contains:

```python
headers = {
    'x-api-key': self.settings.tavus_api_key,
    'Content-Type': 'application/json',
}
```

The end-conversation request must also use `x-api-key`.

### Tavus can create a conversation but cannot call the custom LLM

Check:

1. Tavus Custom LLM Base URL is exactly:

   ```text
   https://virtual-german-tutor-743231335063.us-central1.run.app/api/tavus/llm
   ```

2. The Tavus Custom LLM API key exactly matches `TAVUS_LLM_AUTH_TOKEN`.
3. Do not put `/chat/completions` in the Base URL; Tavus adds it.
4. The Cloud Run service allows unauthenticated HTTP access. The application still protects the LLM route with its Bearer token.

### Vertex AI returns a permission error

Confirm that:

- `aiplatform.googleapis.com` is enabled.
- The Cloud Run runtime service account has `roles/aiplatform.user`.
- `GCP_PROJECT_ID` and `GCP_REGION` are correct.
- The configured Gemini model is available in the selected region.

### Dependency conflicts involving Streamlit, Starlette, or protobuf

Do not install this application's dependencies into a shared/global Python environment. Use a dedicated virtual environment:

```powershell
py -3.11 -m venv .venv
Set-ExecutionPolicy -Scope Process Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r backend\requirements.txt
python -m pip check
```

Streamlit should not be installed into this project's environment because its Starlette requirements can conflict with the pinned FastAPI version.

### Inspect Cloud Run logs

In the console, open:

**Cloud Run → virtual-german-tutor → Logs**

Or use Cloud Shell:

```bash
gcloud run services logs read virtual-german-tutor \
  --region us-central1 \
  --limit 100
```

Do not paste API keys or authentication tokens into logs or support messages.
